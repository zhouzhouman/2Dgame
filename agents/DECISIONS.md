## D-001 ｜ 2026-10-27 ｜ 分辨率定为 640×440

- **决定**：以工程 `project.godot` 为准，基准 640×440，16px 地块，整数缩放。
- **理由**：34×22 地图 = 544×352，加底部对话框 62px 才够放。640 是 320 的整数倍，像素仍整格。
- **影响**：技术选型文档 §7 的 640×360 作废；所有 UI 线框按 440 高重算。
- **推翻条件**：地图缩到 30×18 以下，或改为相机跟随全屏。

## D-010 ｜ 2026-10-28 ｜ 字体以普通文件入库，Git LFS 推迟

- **决定**：仓库内把 `filter.lfs.*` 置为 no-op，字体以真实内容（24,744,500 字节）入库；同时移除会自动生成的 LFS 钩子（`pre-push` / `post-commit` 等），因为它们在没有 git-lfs 时会直接拦截 `git push`。
- **理由**：本机**没有安装 git-lfs**，但系统级 gitconfig 声明了 LFS 过滤器，结果是凡被 `.gitattributes` 标记的路径在 `git add` 时直接失败；仓库里那个字体当时只是一个 133 字节的指针，推上去别人 clone 会拿到文本文件而不是字体。
- **影响**：`Juhuo/.gitattributes` 的 LFS 规则保留但当前不生效（无 filter 即为普通文件）；24.7MB 低于 GitHub 单文件 100MB 限制，clone 下来开箱即用。
- **推翻条件**：正式像素图与音频进场、仓库体积上到百兆级时，装 Git LFS 并执行 `git lfs install`，规则自动恢复。

## D-015 ｜ 2026-10-28 ｜ 催促步长取 8 半刻（4 刻），以规则卡为准

- **决定**：`NUDGE_STEP = 8` 半刻（4 刻），不是 4 半刻。E1 按派单写的 4 半刻实现，以规则卡 `rule_time_clock.md §4` 的默认值与敏感度分析为准。
- **理由**：规则卡算过敏感度——4 半刻会让催促每 2 刻响一次，压过主线节拍；而白幡村"每 4 刻死一个病人"才是这一关的论题，催促不能盖过它。催促次数上限仍是 5（与 schema §C 的 `nudges` 0–5 一致）。
- **影响**：E1 改步长并同步测试期望；E2 接线按 4 刻一次。
- **推翻条件**：G1 手感实测觉得催促太稀。

## D-016 ｜ 2026-10-28 ｜ 未知 hub 时全局旗标仍可读

- **决定**：`FlagStore.Has(name, hub)` 在 hub 未知时，**先查全局**；全局没有才返回 false。全局旗标不属于任何空间，不该因为 hub 拼错就消失。
- **理由**：规则卡公式是"全局有键 > 局部 > false"，而派单里"未知 hub 一律 false"指的是局部查不到。两种读法冲突时以规则卡的**语义**为准：全局优先。
- **影响**：E1 改一处判定；`known.clues` 只增不删的接线位置不受影响。
- **推翻条件**：若将来出现"全局旗标必须限定空间"的玩法需求。

## D-017 ｜ 2026-10-28 ｜ 旗标名两种写法都认

- **决定**：`IsValidName` 同时接受下划线式（旧式，如 `knows_herb_path`）与点号式（新式，如 `序章.账册.已读`）。写入时不拒绝旧名。
- **理由**：规则卡 §1.1 只允许下划线，但派单要求兼容两种。旧名已经写进 120 行 CSV 与正篇接口文档，改名要一次全量重导；新名用点号更利于分域。
- **影响**：新旗标建议一律用点号式；旧名冻结在白名单里。
- **推翻条件**：v3 统一改名时，本条作废。

## D-018 ｜ 2026-10-28 ｜ `SearchPoint.Cost` 由 double 改 int

- **决定**：把 `SearchPoint.Cost` 从 `double` 改成 `int`（schema §A.3 第 3 条的要求；CSV 里全部是整数 "1"）。
- **理由**：刻是半刻整数记账的，字段用浮点迟早会出现 0.1 这种没法解释的值。
- **影响**：改 `SearchPoint.cs` 与 `PointTable.cs` 的解析；既有测试同步；CSV 内容不变。
- **推翻条件**：若将来需要 0.5 刻的搜点，那时再引入"半点"字段而不是回到 double。

## D-019 ｜ 2026-10-28 ｜ CI 不塞未验证的容器 job；关卡可达性改用 Core 单测守

- **决定**：CI 保持三个 job（单测 / 内容校验 / Core 纯净性），**不加入** `godot-ci` 容器 job（既不出包也不做无头冒烟）；关卡可达性由 Core 的 `ReachAudit` 单测守住（S1-13）。
- **理由**：本机没有 docker，Docker Hub API 与 raw.githubusercontent 都不可达，`barichello/godot-ci` 的 mono 4.7.2 tag 无法核实——把没验过的镜像写进工作流，等于给仓库埋一颗必红的雷。而可达性本来就是纯数据判断，搬进 Core 后**现有单测 job 就能守**，不需要任何 Godot 二进制。
- **影响**：`--audit` 的判定逻辑与 Core 单测必须完全一致（S1-13 要求照搬，不许自己发明规则）；出包 job 等能验证镜像后再加。
- **推翻条件**：能确认镜像 tag 且本地能跑通容器时，另开一票恢复容器 job。

## D-020 ｜ 2026-10-28 ｜ 本地门禁统一入口 `tools/smoke.sh`

- **决定**：新增 `bash tools/smoke.sh`（`--fast` 跳过引擎自检），按顺序跑编译 / 单测 / 校验器自测 / 内容校验 / Core 纯净性 / 可达性 / 七关串联 / 引导五步 / 存档自检，任一项失败即退出码 1 并点名失败项。

- **推翻条件**：无。
