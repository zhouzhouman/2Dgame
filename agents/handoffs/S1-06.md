## 语义（重要，接线时必须照此）

| 规则 | 说明 |
|---|---|
| 节拍**不锁空间** | 玩家任何时候都能在 7 个空间之间走（`--chain` 仍然通），节拍只决定"故事现在期望你做什么" |
| 早到不算完成 | `day` 没到就是 `TooEarly`，`Complete` 返回 false |
| 不能跳 | 前面没做完，后面 `requires` 不满足 → `Locked` |
| 重复完成幂等 | 对已完成的节拍再 `Complete` 返回 false，旗标计数不变 |
| **`Complete` 不推进日历** | 推进由调用方决定（谁该消耗一天，是玩法问题，不是状态机的问题） |
| **`ToState` 不写旗标** | 旗标进 `SaveState.Flags`，节拍只记"做完了哪几拍"；两处都写会出现同一事实两个副本 |
| 坏数据只关门 | `requires` 语法错 → 这一拍永远 `Locked`，**不抛异常**；但 `sets` 里的非法旗标名**加载即抛**（否则会静默停摆） |

## 语法裁定（S1-06b）

`requires` 全工程**只有一种方言**：裸旗标名 + `& | !` + 括号。
- 数据侧写成 `beat.b01.done`（三段点号，符合 `FlagStore.IsValidName`）；两段式 `b01.done` 会被判非法。
- Core 侧**不再兼容** `has(...)`——E1 一开始加了脱壳正则，P0 裁定删除：同一列两种写法，下一个写数据的人一定会踩。
- `tools/validate.py` 的 E10 对 `has(...)` 与两段式 `sets` 名判**硬错**。

## 留给 E2 的两个坑（E1 原话）

1. `Complete(beat)` **不推进日历**——推进是玩法决定，别以为它会自己跳到下一天。
2. `ToState()` 只回"做完了哪几拍"，**不写旗标**；旗标走 `SaveState.Flags`，两边都写会出现同一事实两个副本，读档时互相打架。
