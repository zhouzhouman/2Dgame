## 为什么它值得存在

**第一次跑就抓到一个会卡死流程的 bug**：
`b05→b06`（hub4）、`b08→b09`（hub6）、`b11→b12`（hub7）是**同一空间连着两拍**。
原来的弹窗只在"进入空间"时触发，第二拍永远没机会弹；而七个空间只能往前走、走不回去——
玩家会**永久卡在第 6 拍**，序章不可通关。

修法：选项落定后、以及读完一页后，都再问一次"下一拍是不是也是选择型"。

## 输出

```
[通关] 1/12 b01 焚账        hub1 第1天 刻 0/8
...
[通关] 合计：12/12 拍，第 30 天，用刻 16（预算 88，超支 0 空间）
[通关] 分空间：hub1 5/8  hub2 2/10  hub3 2/16 ... （实际/预算）
[通关] 结论：可以通关
```

失败时 `exit 1` 并指出卡在哪一拍、为什么，例如：
`结论：不能通关（第 3 拍 b03 第一口锅：选项面板没有弹出来）`

## 它证明什么、不证明什么

| 证明 | 不证明 |
|---|---|
| 十二拍真的能按顺序走完，没有断链 | ❌「2.6–3.5 小时」——主线只吃 **16 刻**，88 刻预算基本是留给探索的 |
| 主线路径不超刻预算 | ❌ 玩家真实手感（要人玩一遍） |
| 跑前跑后玩家存档字节不变 | ❌ 全收集路线的可达性（那是 `--audit` 的事） |

**结论**：这是"能不能通关"的门禁，不是"好不好玩"的度量。真实时长仍需 playtest。

## 用法

```bash
GODOT="$(python tools/godot_path.py)"
"$GODOT" --headless --path Juhuo -- --playthrough          # exit 0 = 能通关
"$GODOT" --headless --path Juhuo -- --playthrough --pick=2 # 选项都选第 3 项
bash tools/smoke.sh                                        # 已纳入第 10 项
```
