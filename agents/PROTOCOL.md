# PROTOCOL · 协作协议

**所有智能体必读。与 CANON 冲突时以 CANON 为准；本文件管"怎么合作"，不管"做什么"。**

---

## 1 三条总则

1. **一个文件只有一个写者。** 不在你的所有权清单里的路径，只读。要改，发 CHANGE 或请 owner 开票。
2. **聊天不算数。** 任务、决定、交接必须落到 `BOARD.md` / `DECISIONS.md` / `handoffs/`。
3. **没有证据的完成等于没完成。** 每条"完成"必须附可复现的命令与关键输出。

---

## 2 消息信封

标题行必须带票号。正文不超过 30 行，细节放交接单。

### 2.1 TASK（P0 → 执行者）

```
[TASK <票号>] <一句话标题>
目标：<可观察的结果，不写"优化一下"这种话>
输入：<文档章节 / 文件 / 数据>
允许写：<具体路径，逗号分隔>
不许做：<最容易越界的三件事>
验收：1) ... 2) ... 3) ...（每条可机器或肉眼验证）
证据：<要交的命令、截图、报告>
```

### 2.2 REPORT（执行者 → P0）

```
[REPORT <票号>] DONE | PARTIAL | BLOCKED
改动：<文件列表，一行一个>
证据：<命令 + 关键输出，≤20 行>
风险：<会影响谁 / 哪个门禁>
下一步：<建议，一句话>
```

### 2.3 REVIEW（评审者 → P0 + 作者）

```
[REVIEW <票号>] PASS | CHANGES | REJECT
发现：
- <file:line> 问题 → 建议
- ...
必改：<≤3 条，按严重度排序>
```

### 2.4 BLOCK（任何人 → P0）

```
[BLOCK <票号>] 需要：<一句话>
原因：<试过什么，为什么不行>
选项：A ... / B ...
默认：若无回复，我按 A 做（24 小时内）
```

### 2.5 CHANGE（任何人 → P0）

```
[CHANGE <编号>] <一句话>
现状：<哪条决策 / 哪个文档>
影响：<系统 / 数据 / 文本 / 存档>
成本：<人时 + 需要的回归测试>
建议：<做 / 不做 / 延后>
```

---

## 3 任务状态机

```
BACKLOG → READY → CLAIMED → DOING → REVIEW → DONE
                       ↓        ↓
                    BLOCKED   CHANGES → DOING
                       ↓
                    DROPPED
```

- 一个 agent 同时只有 1 张 DOING。
- 全局 REVIEW ≤ 3 张。
- BLOCKED 必须在当轮上报，不许猜着做。
- 票没写验收标准，不许进 READY。

## 4 评审

| 改动 | 作者 | 评审 | 重点 |
|---|---|---|---|
| Core | E1 | Q1 | 边界值、确定性、存档兼容 |
| Game / UI | E2 | E1 + A1 | 有没有绕开 Core；视觉是否符合册子风 |
| 文本 | D2 | D1 + P0 | 设定一致；抽读三段 |
| 数据 | D3 | Q1 + D1 | 校验通过；schema 正确 |
| 文档 | owner | P0 | 能不能照着做 |

**作者不能自审。** 评审只提"必改"三条，其余写成建议，避免无限返工。

## 5 上下文纪律

> **并发禁令（2026-10-28 踩出来的）**
>
> 一个执行者**同一时刻只能有一个会话**在跑。
> 派单时如果需要它接着上一轮做（返工票），不要在其原任务尚未结束时"续跑"——
> 那会起第二个会话，两个会话同时改同一批文件：读到半成品、Edit 撞空、互相怀疑"有人在改我的文件"。
>
> 一天里这事发生了两次（E1 的 BeatMachine、D3 的 validate.py），两次都白花了排查时间。
>
> 正确做法：
> 1. 确认原任务**已结束**（收到完成的系统通知）；
> 2. 再发返工票；返工票要自带上下文，不要指望它记得上一轮；
> 3. 如果拿不准原会话是否结束，宁可起一个**全新的执行者**，把要改的文件与契约写进提示词。



- 只读：`CANON.md` + 本文件 + 你的角色提示词 + 当前票面 + 角色必读清单。
- 不读：其他角色的提示词、其他票的交接单、与你无关的二十余份文档。
- 每轮开始先读 `BOARD.md` 的"本轮"区块，不要从聊天记录里回忆任务。

## 6 反作弊（违反即打回，不计工时）

1. 不删测试、不跳过测试、不放宽断言来迁就实现。
2. 不改验收标准让自己通过。
3. 不把未实现功能标 ✅。
4. 不伪造命令输出或截图。
5. 不跨所有权"顺手改"。
6. 不新增系统（新想法写进 DECISIONS 的"待议"）。

## 8 每轮收尾

P0 在每轮结束做四件事：

1. 更新 `BOARD.md` 状态与"本轮"区块。
2. 把新决定追加到 `DECISIONS.md`。
3. 归档交接单到 `handoffs/`。
4. 写 5 行轮次摘要：完成 / 卡住 / 偏差 / 需拍板 / 下一步。
