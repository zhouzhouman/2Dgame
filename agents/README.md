## 怎么开一个会话

每个智能体一个独立会话。第一条消息按这个顺序拼：

```
1. 角色提示词全文（prompts/xx.md）
2. CANON.md 全文
3. PROTOCOL.md 全文
4. 当前票（从 BOARD.md 复制，含验收与允许写的路径）
5. 一句话：现在开始，完成后按 REPORT 格式回报，不要做票外的事。
```

不要把所有设计文档一次性塞进去。角色提示词里已经写了"必读清单"，让它自己按需读。

### 第一条消息模板（直接复制）

```
你是《举火》项目的 <角色名>（<代号>）。

<粘贴 prompts/xx.md 全文>

---
<粘贴 CANON.md 全文>
---
<粘贴 PROTOCOL.md 全文>
---
当前票：
<从 BOARD.md 复制整行 + 在下方补全目标/输入/允许写/不许做/验收/证据>

---
开工前先做两件事：
1. 用不超过 5 行复述你理解的验收标准；
2. 列出你打算读的文件（不要读清单以外的）。
然后开始。完成后按 REPORT 格式回报，不要做票外的事。
```

## 启动顺序（重要）

1. **只开 P0**，完成 G0：裁 7 条冲突、写 CANON、冻结 schema。
2. G0 通过后开 D1/D3/E1/Q1，做 S0 的四张票。
3. S0 全绿后再开 E2/A1；第 3 周起最多 3 个并行 worker。
4. **不要第一天八个全开。** 契约没稳时并行，只会制造合并冲突。

---

## P0 每轮要做的四件事

1. 更新 `BOARD.md`（状态、本轮、阻塞）。
2. 新决定追加到 `DECISIONS.md`。
3. 交接单归档到 `handoffs/<票号>.md`。
4. 写 5 行轮次摘要。

---

## 怎么判断一个 agent 在胡说

- 报告"已完成"但没给命令输出 → 打回。
- 改了不在允许路径里的文件 → 回滚。
- 说"测试都过了"但没说是哪几条 → 让它贴 `dotnet test` 尾部。
- 把未实现功能标 ✅ → 以 Q1 的 README 状态表为准。
- 反复"优化"同一处却不给验收证据 → 停票，换人。

## 最小的可用组合

如果只想先跑起来，用这三份就够：

**P0 + E1 + Q1**：一个拆票、一个写 Core、一个验收。
文本与美术可以后补，但契约和测试必须先立起来。
