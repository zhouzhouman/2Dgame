# 规则：刻（软时钟）

**版本** 1 ｜ **票号** S0-02 ｜ **唯一数值源**：本文件 §2 的预算表与 §3 的消耗表。代码里的常量必须注释指回本节。
**上游** 关卡设计 v1.0 §1.1 / §5.1、数据表规范 v1.0 §6、CANON 3「首次对话不消耗刻」（D21）

## 输入

| 名称 | 类型 | 范围 | 来源 |
|---|---|---|---|
| `ke_half` | int | `0`–`2B+16` | `save_state.hubs[h].ke_half` |
| `B` | int | 见 §2，`8`–`20` | 本文件 §2（常量，代码指回此处） |
| `cost` | int | `0`–`3` | `points.csv.cost` |
| `n_search` | int | `0`–`120` | `hubs[h].searched` 变化次数（含重搜、含空点） |
| `n_talk_repeat` | int | `0`–`28` | `known.npcs[].again` 变化次数 |
| `n_dose` | int | `0`–`10` | 给药救人数 |
| `n_interrupt` | int | `0`–`99` | 被 NPC 看见而打断的次数 |
| `n_interrogate` | int | `0`–`33` | 被连续发现第 3 次触发的盘问次数 |
| `n_rest` | int | `0`–`7` | 睡觉/休息次数 |
| `n_leave` | int | `0`–`7` | 离开当前空间次数 |
| `NUDGE_STEP` | int | 默认 `8`，区间 `4`–`16`（半刻 = 4 刻） | 可调系数（§4） |
| `OVERFLOW_CAP` | int | 默认 `16`，区间 `0`–`24`（半刻） | 可调系数（§4） |

---

## 公式

```
ke_half = 2*(n_search + n_talk_repeat + n_rest + n_leave) + 1*n_dose + 4*n_interrupt + 4*n_interrogate   ，写入时 clamp 到 [0, 2B+OVERFLOW_CAP]
ke_used = ke_half / 2                    （整数除，向下取整）
ke_left = max(0, B - ke_used)
nudges  = 0                       若 ke_half <  2B
        = 1 + (ke_half - 2B)/8    若 ke_half >= 2B   （整数除；NUDGE_STEP=8 半刻 = 4 刻）
max_cover = (2B - 2*(n_talk_repeat + n_rest + n_leave) - n_dose - 4*(n_interrupt+n_interrogate)) / 2   （向下取整，= 本空间最多还能搜几个点）
deaths(hub3) = min(3, ke_used/4)         （躺着的人；从进入起算，不只在越线后）
```

**逐条读法**

- `n_search` 每 +1 就 +2 半刻，**不论首次、重搜、空点**（`points.cost=1` 时）。
- 首次对话、赠礼、Esc 中断的对话、未满足条件的知识门：**不进任何一项**（D21）。
- `n_interrogate` 是**替代**不是叠加：第 3 次连续被发现只记 `n_interrogate+1`（4 半刻），不再记 `n_interrupt`。
- `deaths` 与 `nudges` 用同一个步长（4 刻）：进入白幡村第 4/8/12 刻各死一人，第 16 刻（刚好用完预算）三人全死光——这正是"你翻得越多，时间过得越快"（关卡设计 §3.3）与"每 4 刻死一个病人"（§5.1、数据表规范 §8-9）的统一写法。

## 边界

- **除零**：公式里没有变量除数（2 与 4 是常量）。`B` 缺失或 `≤0`：按 `B=8` 处理并打一条错误日志，**不允许 `B=0` 静默生效**。
- **下限**：`ke_half ≥ 0`，不接受负数；`ke_left` 下限 `0`；`nudges` 下限 `0`。
- **上限**：`ke_half ≤ 2B + OVERFLOW_CAP`（默认 `2B+16`，即最多再记 8 刻欠账）；`nudges ≤ 1 + OVERFLOW_CAP/NUDGE_STEP = 3`。超出部分**丢弃不记**，防止死循环与存档膨胀。
- **空值**：`cost` 缺失/空串 → 按 `1`；`cost` 非整数 → **向下取整**后 clamp `0`–`3`。
- **取整方式**：一律整数除向下取整。`ke_used` 向下取整意味着「用了半刻」在界面上仍显示 `0`——**对玩家有利，故意如此**（0.5 刻不显示成 1 刻）。
- **结算顺序**（每次动作严格按此序，保证可复现）：
  1. 校验动作是否成立（够得着、条件满足、未打断）；
  2. 计算本条动作的半刻增量；
  3. `ke_half += 增量` 并 clamp；
  4. 重算 `ke_used` / `ke_left` / `nudges`；
  5. 结算该动作的世界后果（发 `loot`、置 `set_flag`、置 `searched`、扣病人命）；
  6. 若 `nudges` 增加，**动作结算完之后**才播催促（玩家看到自己干了什么，再看到代价）；
  7. 存档。

## 例外

1. **首次对话 0 刻**（D21）。含赠礼、含被 Esc 中断的首次对话（`met=true` 一旦成立就不再免费）。
2. **Esc 打断蹲下（3 秒动画）**：不扣刻、不置 `searched`、不算 `n_search`——动画不是动作。
3. **知识门未满足条件**：按 E 无反应，0 刻；`requires` 满足后"变成" `surface`，从这一刻起才收费。
4. **打断不是失败**：只扣刻与疑心，不加通缉、不驱逐、不置 `searched`（数据表规范 §2）。重搜仍出 `text_once`。
5. **超预算不锁操作**：`ke_left=0` 之后仍可搜、可谈、可走动。只按 `nudges` 递增播催促事件（Hub1 吴管事破门 / Hub3 每 4 刻死一个病人 / Hub4 寿宴开始 / Hub6 使者离开），**永不逐出、永不通关失败**。
6. **催促不额外收费**：催促本身 0 刻，只推进该空间的代价事件；`nudges` 单调不减，防止反复触发同一句。
7. **同一空间内不随时间流逝回血**：`ke_half` 只增不减，日切、节拍推进、进出子区域都不重置；只有 `Load(hub)` 进入**新**空间时才从 0 起算。
8. **正篇不用刻**：正篇用「每月 3 点行动力」（设计文档 17.3）。两套单位不互换、不折算。

## 验收

> 全部用整数核对，允许误差 `0`。种子无关（本规则无随机）。

| # | 用例 | 输入 | 期望输出 |
|---|---|---|---|
| 1 | **剩 0 刻的瞬间** | hub3，`ke_half=30`（15 刻），搜 `bf_02`（cost 1） | `ke_half=32`、`ke_used=16`、`ke_left=0`、`nudges=1`；允许继续操作 |
| 2 | **刚好超预算** | 承上，再搜 `bf_04` | `ke_half=34`、`ke_used=17`、`ke_left=0`、`nudges=1`（`34-32=2 < 8`）；文本正常输出，不逐出 |
| 3 | **连续空搜** | hub1，`B=8`（`2B=16`），连搜 5 个空点 `h1_e01`–`h1_e05` | `ke_half=10`、`ke_used=5`、`ke_left=3`、`nudges=0`；再搜 `h1_01`–`h1_03` → `ke_half=16`、`ke_used=8`、`ke_left=0`、`nudges=1` |
| 4 | **首次对话免费（D21）** | hub2，`B=10`，首次见沈砚 + 首次见老仆，各说完整段 | `ke_half=0`、`ke_left=10`；再谈沈砚一次 → `ke_half=2`、`ke_used=1` |
| 5 | **半刻取整** | hub3 给药救 D | `ke_half=1`、`ke_used=0`（显示 0 刻）；再救 F → `ke_half=2`、`ke_used=1` |
| 6 | **打断** | hub3 在衙役甲 G 视野（4 格、90°）内搜 `bf_08`（`watch_npc=G`） | `ke_half+=4`、疑心 +10、`searched` 不含 `bf_08`；重搜仍输出 `text_once` |
| 7 | **越线封顶** | 持续超支到 `ke_half` 理论值 `2B+30` | 实记 `2B+16`、`nudges=3`，不再增长 |
| 8 | **离区计费归属** | hub2 剩 1 刻时走向出口 | 离开前 `ke_half += 4`（记在 hub2），进入 hub3 时 `ke_half=0`、`ke_left=16` |
| 9 | **覆盖率（设计意图回归）** | hub3，8 段必看对话（全免费）+ 0 打断 | `max_cover=16`，`16/29=55%`，与数据表规范 v1.1 修订一致 |
| 10 | **病人死亡节拍** | hub3 进入后只用搜查推进到 12 刻（12 次） | `deaths=3`，三个 `sick` 全 `dead`；若其中给药救了 2 人 → `ke_used=13`、`deaths=3`，但被救者仍 `alive`（药优先于死亡判定） |

**敏感度**：系数动 10% 影响最大的是 **`B`（预算）**——`hub3` 从 16 → 18 刻（+12.5%），可搜点数从 16 → 18（+2 点，覆盖率 55% → 62%）；其次是 `NUDGE_STEP`（8 → 9 半刻 ≈ +12%，死人与催促的节拍从 4 刻变 4.5 刻，覆盖率不变，但 Hub3 的三人死法变松）。
**注意**：`cost` 系数（1 刻）粒度太粗，±10% 在半刻单位里等于 0，**不可作为调参旋钮**；要调覆盖率请动 `B`。

## 可调系数

| 系数 | 默认 | 合理区间 | 单位 | 动它的后果 |
|---|---|---|---|---|
| `B`（7 个空间分别设） | 8/10/16/20/12/14/8 | ±25% | 刻 | 直接决定覆盖率与"看不完"的痛感；**首选旋钮** |
| `K_SEARCH` | 1 | 0.5–2 | 刻 | 与 `B` 效果等价但会破坏 `points.cost=1` 的数据语义，不推荐 |
| `K_REPEAT_TALK` | 1 | 0–2 | 刻 | 调 0 = 玩家可无限回看对话，情报变廉价 |
| `K_DOSE` | 0.5 | 0–1 | 刻 | 调 0 = 救人不痛，Hub3 的道德压力归零 |
| `K_INTERRUPT` | 2 | 1–3 | 刻 | 守卫的威慑力 |
| `K_INTERROGATE` | 4 | 2–6 | 刻 | 第三次被发现的惩罚拐点 |
| `K_TRAVEL` | 2 | 1–3 | 刻 | 出口的"沉没成本"，影响"要不要再回头搜一个" |
| `NUDGE_STEP` | 8（= 4 刻） | 4–16 | 半刻 | 催促与病人死亡密度；调小 = 更急，但不改覆盖率 |
| `OVERFLOW_CAP` | 16 | 0–24 | 半刻 | 越线后还能磨多久；设 0 = 到线即锁（**禁止**，违反验收 8） |
