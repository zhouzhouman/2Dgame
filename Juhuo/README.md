## 一分钟跑起来

```powershell
# 1. 编译
dotnet build Juhuo.sln

# 2. 打开编辑器
godot --path .

# 3. 或者直接运行
godot --path .
```

命令行验证（不开窗口）：

```powershell
godot --headless --path . --quit
# 期望输出：[举火] 载入 120 个可搜点，当前 hub3 有 29 个
```

### 开发辅助参数

参数写在 `--` 之后，可以叠加。

| 参数 | 作用 |
|---|---|
| `--shot` | 开窗跑一帧，存 `shot.png` 后退出 |
| `--hub=hub4` | 直接进某一关 |
| `--audit` | **逐关自检**：每件可搜物四周有没有能站人的格子，只报"够不着" |
| `--exit` | 站到出口按一次 E，验证真的能进下一关 |
| `--atexit` | 站在出口但不按 E，用来看底部提示 |
| `--touch` | 站到某件东西的**斜角**上按 E，验证斜角能不能交互 |
| `--walk` | 从起点按住左走三秒，验证通道通不通 |
| `--spy` | 把玩家挪到衙役眼皮底下，看视野扇形与红屏 |
| `--talk` | 站到第一个 NPC 旁边说一句话 |
| `--demo` | 挪到第一件东西旁边搜一次，看完整界面 |
| `--chain` | 连着走完七个场景，验证换关 |
| `--nearnpc` | 站到第一个 NPC 旁边但不说话，看"E 交谈"提示 |
| `--tutorial` | 强制重看新手引导（忽略进度文件） |
| `--no-tutorial` | 关掉新手引导（截图用） |
| `--tutstep=3` | 直接把引导拨到第 N 步（看版式） |
| `--tutrun` | 把五步一次走完，验证引导推得动、进度真的落盘 |
| `--help` | 打开操作说明面板 |

```powershell
godot --path . -- --shot --hub=hub1 --atexit
# 生成 shot.png
```

## 新手引导与防误操作

**引导不弹窗。** `Src/Game/Onboarding.cs` 只记"第几步"，推进条件全部来自玩家真的做了什么：
走出去 → 按住 Ctrl → 翻了一件东西 → 和人说了话 → 走到出口。每一步都是他自己做的，所以不打断。

- 提示只有底部一行（`Panel` 高 30px），不用遮罩、不用暂停
- 四个键、出口长什么样、这一关要做什么，都写在 `H` 的操作说明里
- 看过一次写进 `user://progress.cfg`，下次不再出现

**必要步骤都加了校验：**

| 情况 | 处理 |
|---|---|
| 对话开着按 E | 当作"看完了"，关掉对话，**不会**再搜一遍同一件东西 |
| 对话开着按 WASD | 人物不动（读字时误触不会把人飘走） |
| 出口还有没看的地方 | 第一次按 E 只提醒"还有 N 处没看"，第二次才走 |
| 站到没东西的地方按 E | 明确回一句"这里没什么可翻的" |
| 35 秒没翻过东西 | 提醒一次 Ctrl（每处只提醒一次） |
| 站着的人没有台词 | 载入时打 `[哑巴]` 日志，内容缺口当场暴露 |

## 工程结构

```
Juhuo/
├── project.godot            引擎配置（640×440 / 16px 地块 / Nearest / 像素吸附）
├── global.json              锁 .NET SDK 8.0.427
├── Directory.Build.props     统一 LangVersion / Nullable
├── Juhuo.csproj              Godot 主工程（只编译 Src/Game）
├── Juhuo.sln                 四个项目串起来
├── Content/                 内容表（数据驱动，改这里不用改代码）
│   ├── data/points.csv      120 个可搜点
│   └── maps/*.txt           7 张地图的地形
├── Scenes/Main.tscn         当前唯一场景
├── Src/
│   ├── Core/                ★ 纯 C#，零 Godot 引用
│   ├── Application/         会话与流程
│   └── Game/                Godot 节点与表现
├── Tests/Core.Tests/        xUnit（7 个测试）
└── Assets/Fonts/            字体说明（发行前必须替换系统字体）
```

### 三层架构（硬规定）

```
Src/Game         → 可以用 Godot
Src/Application  → 不引用 Godot
Src/Core         → 不引用 Godot，CI 会检查
```

**为什么要这么分**：数值逻辑（经济、民心、战斗）必须能脱离引擎跑单测和无头模拟。`Core` 里出现 `using Godot` 就是事故。

`Juhuo.csproj` 里已经显式 `Compile Remove` 掉了子目录，否则 Godot 的通配会把三层代码全编译进主程序，分层就白做了。

## 关键约定

**分辨率 640×440，不是 320×180。**

34×22 的地图在 16px 地块下是 544×352，加上底部对话框（62）才够放，所以高度是 440。宽度 640 是 320 的整数 2 倍，像素仍然是整格的。

**地块 16×16，角色 16×24，所有贴图必须整数缩放。**

**交互判定是"八方向相邻"，不是圆形半径。**

站在物件斜角（距离 1.41）也要能按 E。斜角额外要求两个正交邻居至少一个站得下，避免隔着墙角摸东西。

**出口必须在边界墙上开一个口子。**

如果出口那一格外面还是墙，玩家走到头只看见一堵墙，画面上没有任何东西告诉他"这里能出去"。开口写在 `tools/gen_prologue_data.py` 的 `EXITS` 表里，坐标必须和 `SceneConfig.cs` 一致。

**室内外用"从起点灌"来判，不靠固定圈数。**

房间被墙和门洞挡住，从场景起点灌不到的就是室内。以前按"第几圈撒种子"，小院只有 10 行高，第 3 圈正好落在两间厢房的地面上，房间就成了院子（长草、不画屋顶）。

**不要用编辑器改 `Content/*.csv`。** 数据由 `../tools/gen_prologue_data.py` 生成，编辑器改动会被覆盖，也容易把坐标改错（之前出过一次同格重叠）。

正确的改法：

```
改 tools/gen_prologue_data.py → 重新生成 → 同步地图/CSV → dotnet build
```

## 测试

```powershell
dotnet test Tests/Core.Tests/Core.Tests.csproj
godot --path . -- --audit        # 120 件东西能不能全部够得着
```

16 个单元测试：CSV 引号/BOM 解析、120 条总数、白幡村 29 条、坐标取点、知识门数量、重复文本非空、
进度文件读写与坏行容错、台词表"按坐标查 / 按名字查"两种口径。

`--audit` 是关卡级自检：只要有一件东西四周没有能站人的格子，它就会点名报出来。
`--tutrun` 是引导级自检：五步里只要有一步的条件永远不成立，它就停在那一报出来。
