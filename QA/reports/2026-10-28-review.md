### 5.3 门禁覆盖缺口（实测发现，属 Q-007）

纯净性门禁**只查 `using Godot` 与 `GodotSharp` 两个字符串**。实测注入完全限定名的 Godot 引用：

```csharp
// Juhuo/Src/Core/Probe.cs
public static Godot.Vector2 Pos() => new Godot.Vector2(1, 2);
```

- `grep "using Godot"` → **无匹配，job 仍然绿**
- `grep "GodotSharp"` → **无匹配，job 仍然绿**

### 6.5 干净克隆的唯一脏文件：`npcs.csv` 行尾漂移（→ Q-006）

```

 M Juhuo/Content/data/npcs.csv
```

**实测定位**（不是内容差异，是行尾差异）：

| 检查 | blob（库中） | 工作区 | `cmp` |
|---|---|---|---|
| 字节数 | 8435 | 8435 | **IDENTICAL** |
| CR 数 | 31 | 31 | — |
| LF 数 | 31 | 31 | — |
| 前 16 字节 | `EF BB BF 22 68 75 62 22...` | 同 | — |

```
$ git hash-object Juhuo/Content/data/npcs.csv
aceb2f9728937e75dcd74639294dce9f4708f0a4      ← 过滤后（LF 归一）
$ git rev-parse HEAD:Juhuo/Content/data/npcs.csv
0dfac7121df53204b3bb283d8930a603b6db594d      ← 库中存的（CRLF）
warning: in the working copy of 'Juhuo/Content/data/npcs.csv', CRLF will be replaced by LF the next time Git touches it
```

**根因**：`Juhuo/.gitattributes` 声明 `*.csv text eol=lf`（LF 归一），
但 `npcs.csv` 在**该规则生效前**就以 CRLF 入了库，**blob 里存的是 CRLF**（31 CR）。
于是：工作区文件（CRLF）→ `text eol=lf` 过滤 → 归一成 LF → 哈希 ≠ blob → **永久显示为已修改**。

**全仓漂移范围（逐文件 hash 比对，含中文名）**：

```
DRIFT: Juhuo/Content/data/npcs.csv
（仅此 1 个，其余 全部匹配）
```

**影响**：
1. **任何人克隆仓库，`git status` 一开始就不干净**（会看到 npcs.csv 被改）。
2. **下次谁碰这个文件并提交，会把 CRLF→LF 的全文件改写混进 diff**（31 行全变），污染 code review。
3. **CI 当前不受影响**（`validate.py` 读的是工作区文件，且解析器容忍 CRLF —— 有单测 `忽略BOM与CRLF` 覆盖），故三项门禁仍全绿。
4. 根目录三个 `举火_*.csv`（`举火_文本表_v1.0.csv` / `举火_序章数据_全关卡_v1.1.csv` / `举火_序章数据_白幡村_v1.0.csv`）**没有 `text`/`eol` 属性**（仓库根没有 `.gitattributes`，`Juhuo/.gitattributes` 管不到根目录）→ **行尾不锁定**。在 `core.autocrlf=true` 的机器上检出会被转成 CRLF。这三条是**源 CSV**，属 P3。

→ **Q-006（P2）**。

## 7 新发现的缺陷

### Q-006 ｜ P2 ｜ 干净克隆后 `npcs.csv` 永久显示为已修改（行尾归一未执行）

- **复现**：
  1. `git clone . D:/tmp/ci-rehearsal`
  2. `cd D:/tmp/ci-rehearsal && git status --porcelain`
  3. 输出：` M Juhuo/Content/data/npcs.csv`
- **期望**：干净克隆后 `git status` 无输出。
- **实际**：上述 1 个文件恒为 modified。
- **根因**：`Juhuo/.gitattributes` 有 `*.csv text eol=lf`，但 `npcs.csv` 的 blob 是 CRLF（31 CR / 31 LF），`git hash-object` 归一后（`aceb2f9…`）≠ 库中 blob（`0dfac71…`）。
- **证据**：`git cat-file -s HEAD:Juhuo/Content/data/npcs.csv` → 8435；工作区 CR=31 LF=31；`cmp` blob 与工作区 → IDENTICAL；`git hash-object` → `aceb2f9…` ≠ `0dfac71…`；git 自身告警「CRLF will be replaced by LF the next time Git touches it」。
- **影响**：clone 后工作区不干净；下次提交该文件会混入 31 行全文件改写。
- **修复方向**：执行 `git add --renormalize Juhuo/Content/data/npcs.csv` 并提交归一后的版本（与 `Juhuo/.gitattributes` 注释里已写明的做法一致）。
- **owner**：D3（`Content/data/**` 与 `tools/**` 属 D3）。

### Q-007 ｜ P2 ｜ Core 纯净性门禁只匹配两个字符串，漏判完全限定名的 Godot 引用

- **复现**：
  1. 在 `Juhuo/Src/Core/Probe.cs` 写入 `public static Godot.Vector2 Pos() => new Godot.Vector2(1, 2);`

  3. 跑 `dotnet build Juhuo/Src/Core/Core.csproj` → `error CS0246: 未能找到类型或命名空间名"Godot"`

- **实际**：grep 门禁判绿；靠编译门禁（CS0246）兜底拦住。

- **影响**：`Core.csproj` 不引用 `GodotSharp`，因此实际漏不过 CI；但一旦有人给 Core 加上程序集引用，纯净性门禁就形同虚设。门禁注释自称「机器校验，不靠自觉」，当前实现是「靠别人看得见」。

### Q-008 ｜ P2 ｜ CI 从仓库根执行 `dotnet build`，不受 `Juhuo/global.json` 的 SDK 锁定约束

- **复现**：
  1. `cd D:/我的小想法游戏 && dotnet --version` → **9.0.300**
  2. `cd D:/我的小想法游戏/Juhuo && dotnet --version` → **8.0.427**
  3. `git ls-files | grep global.json` → 只有 `Juhuo/global.json`（**仓库根无**）
- **期望**：CANON §4 规定「`global.json` 锁 8.0.x」，且 CANON §7 把 `global.json` 列为冻结件；CI 命令从仓库根跑，理应吃到这个锁。
- **实际**：`global.json` 只在 `Juhuo/` 下，而 **dotnet 的 SDK 解析从「当前工作目录」向上找 `global.json`，不从工程路径找**。CI 的 `run:` 步骤工作目录是仓库根 → **锁定完全失效**，CI 实际用 runner 上任意可用 SDK。
- **证据**：`dotnet --version` 在两处输出不同（9.0.300 vs 8.0.427）；`Juhuo/global.json` 内容为 `{"sdk":{"version":"8.0.427","rollForward":"latestFeature"}}`。
- **影响**：CI 目前 `actions/setup-dotnet@v4` 装的是 `8.0.x`，碰巧与锁一致，**但这是巧合不是约束**。runner 镜像升级、setup-dotnet 默认值变化、或有人把 `dotnet-version` 改成 `9.0.x`，都会静默用错 SDK，而 CANON 明文要求锁 8.0.x。
- **修复方向**：把 `global.json` 复制/上提到**仓库根**（一份即可，`Juhuo/global.json` 可留可删），或 CI 的每个 `run:` 加 `working-directory: Juhuo`。
- **owner**：E1 / P0（`global.json` 属冻结件）。

### Q-009 ｜ P2 ｜ 仓库根缺 `.gitattributes`，根目录二进制与 CSV 的行尾/二进制属性不受管

### Q-010 ｜ P2 ｜ CI 缺 headless 冒烟 job，`--audit` / `--chain` / `--tutrun` 无人守
