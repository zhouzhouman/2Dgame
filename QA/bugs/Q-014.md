# Q-014 · 内容数据有两个源，且没有同步脚本

- 严重度：P1（内容会悄悄分叉，改一边另一边不知道）
- 发现者：P0（2026-10-28，修 hub4 封死房间时撞见）
- 状态：待修（归 D3）

## 现象

同一批 120 个可搜点，仓库里存了两份：

| 文件 | 谁在用 | 谁在写 |
|---|---|---|
| `Juhuo/Content/data/points.csv` | **游戏运行时读这份** | **没有任何脚本写它**（手工维护） |
| `举火_序章数据_全关卡_v1.1.csv` | 文档、校对、给设计看的 | `tools/gen_prologue_data.py` 生成 |

`README.md` 写的是"改内容要改 `tools/gen_prologue_data.py` 再重新生成，直接改 `Content/data/*.csv` 会被下次生成覆盖"——
**这句话不成立**：生成器只写上面那份文档 CSV，不碰游戏 CSV。

## 后果（已经发生过一次）

修 hub4 东屋被封死的问题时：
1. 先改了生成器、重新生成 → 文档 CSV 变成"堂前鼓 (25,8)"；
2. 游戏仍在读老位置的 (24,8) → 自检还是 2 件不可达；
3. 才发现两份数据根本不是一条链。

如果只改一份就提交，会出现"文档对、游戏错"或反过来，而且没有任何检查会发现。

## 建议修法（按优先级）

1. **让生成器直接产出游戏 CSV**：`gen_prologue_data.py` 同时写 `Juhuo/Content/data/points.csv`（同一份数据、两种格式）。
2. **给 `tools/validate.py` 加一条一致性检查**：两份 CSV 的点位 id / 坐标 / 名称逐条比对，不一致就报错。
3. **修 README 里那句失真的话**：在 1 落地前，如实写"游戏 CSV 目前手工维护，改完两边都要同步"。

## 验收

- 跑一次生成器，两份 CSV 同步变化；
- 手工把任意一份改一个坐标，`python tools/validate.py` 必须报错并指出是哪条；
- README 的说法与实际一致。
