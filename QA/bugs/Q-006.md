# Q-006 · 干净克隆后 `npcs.csv` 永久显示为已修改（行尾归一未执行）

- 严重度：P2（阻塞 G0 签收：影响仓库可提交性，不影响运行时）
- 发现者：Q1（2026-10-28 复核 P0 基线报告 + CI 预演）
- 状态：待修
- 依赖票：无
- owner：D3（`Content/data/**` 属 D3，见 CANON §7）
- 证据报告：`QA/reports/2026-10-28-review.md` §6.5

## 现象

```bash
$ git clone . D:/tmp/ci-rehearsal
$ cd D:/tmp/ci-rehearsal && git status --porcelain
 M Juhuo/Content/data/npcs.csv
```

干净克隆（无任何本地修改）后，工作区**一上来就不干净**。

## 复现步骤

1. `git clone <本仓库> <临时目录>`
2. `cd <临时目录>`
3. `git status --porcelain` → 输出 ` M Juhuo/Content/data/npcs.csv`
4. `git diff --stat` → `31 insertions(+), 31 deletions(-)`（全文件每一行都"变了"）

## 期望

干净克隆后 `git status` 无输出；且库中文件内容与 `.gitattributes` 声明的行尾策略一致。

## 实际

`Juhuo/.gitattributes` 声明了 `*.csv text eol=lf`（LF 归一），
但 `npcs.csv` 在该规则生效**之前**就以 CRLF 入库，**blob 里存的就是 CRLF**。

于是 git 的过滤链出现矛盾：

| 对象 | 内容 |
|---|---|
| 库中 blob（`git cat-file`） | 8435 字节，**CR=31，LF=31**（CRLF） |
| 克隆后工作区文件 | 8435 字节，**CR=31，LF=31**（CRLF），与 blob `cmp` → **IDENTICAL** |
| `git hash-object`（应用 `text eol=lf` 过滤后） | `aceb2f9728937e75dcd74639294dce9f4708f0a4` |
| `git rev-parse HEAD:...`（库中 blob） | `0dfac7121df53204b3bb283d8930a603b6db594d` |

两者不等 → git 判定"工作区被修改"。

git 自己也会告警：

```
warning: in the working copy of 'Juhuo/Content/data/npcs.csv', CRLF will be replaced by LF the next time Git touches it
```

### 全仓漂移范围（逐文件 `hash-object` vs blob 比对，含中文文件名）

```
DRIFT: Juhuo/Content/data/npcs.csv
```

**只有这一个文件**。其余全部匹配。

## 影响面

1. **任何人克隆仓库，`git status` 一开始就不干净**，容易被误判成"本地有改动"而被 `git checkout .` 覆盖掉别人的工作。
2. **下次谁碰这个文件并提交，会把 CRLF→LF 的 31 行全文件改写混进 diff**，污染 code review，且看不出真实改动。
3. **CI 当前不受影响**：`validate.py` 读的是工作区文件，解析器容忍 CRLF（有单测 `忽略BOM与CRLF` 覆盖），三项门禁仍全绿。所以这是一个**不会自己暴露、只会在人身上咬人**的问题。
4. G0 是要打 tag / 推远端的节点，带着一个恒脏的入库文件进 G0 不合格。

## 修复建议

按 `Juhuo/.gitattributes` 注释里已写明的标准做法执行归一：

```bash
git add --renormalize Juhuo/Content/data/npcs.csv
git commit -m "fix(data): npcs.csv 行尾归一为 LF，与 .gitattributes 对齐"
```

归一后 blob 变为 LF 版本，工作区与库一致，`git status` 干净。

**验收**：全新 `git clone` 后 `git status --porcelain` 无输出。

## 备注

- 不要用 `git config core.autocrlf false` 之类的本地配置绕过——那是把问题藏起来，不是修。
- `Juhuo/.gitattributes` 注释里已经写明了「加回来之后先 `git add --renormalize .` 把存量文件转成指针，否则新旧两种形态会混在同一个仓库里」。这次是同一类问题的另一种形态：**规则改了，存量没归一**。
