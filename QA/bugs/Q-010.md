## 期望

CI 里有第四个 job，跑 headless 自检（`--audit` / `--chain` / `--tutrun`），
把关卡数据与引导逻辑纳入常设回归。

## 实际

三条自检命令**只在人工跑基线时验证过一次**（2026-10-27，P0 代跑；2026-10-28 我复核重跑，
结果一致：120 件够不着 0 / 七关通 / 引导完成）。

此后**任何**对 `Content/data/*.csv`、`Juhuo/Src/Game/*.cs`、`tools/gen_prologue_data.py` 的改动，
只要破坏了关卡数据或引导逻辑，**CI 不会报**。

## 影响面

1. **本次所有门禁里唯一一处「报告说已过、但没有任何常设机制保证它继续过」的项。**
   基线报告 §5「已过」里三条（120 件够不着 0 / 七空间串联 / 引导五步自检）全靠这一项兜底，
   而它现在不存在。
2. 这三条恰好是最容易在**内容迭代中被无声破坏**的：
   - `points.csv` 坐标改错 → `--audit` 会报"够不着 N 件"，`validate.py` 未必抓得住（它查坐标越界，但查的是"在地图矩形内"，不是"四周有站人的格"）。
   - NPC 的 `hub` 字段填错 → 七空间串联会断。
   - 引导的条件旗标改错 → `--tutrun` 会卡在某一步。
3. G1 一开就是「序章闭环」，内容改动会变频繁。没有这层保护，每次改动都要人工跑三条命令，
   **门禁形同虚设**。

## 修复建议

在 `ci.yml` 里加第四个 job：

```yaml
  # G0 门禁之四：headless 冒烟。关卡数据与引导逻辑的回归保护。
  smoke:
    name: Headless 冒烟
    runs-on: ubuntu-latest
    steps:
      - uses: actions/checkout@v4

      - name: 装 Godot
        # 4.7.2 mono 版，需与 project.godot 一致
        run: |
          wget -q https://github.com/godotengine/godot/releases/download/4.7.2-stable/Godot_v4.7.2-stable_mono_win64.zip
          # linux runner 应下 linux 版；具体 URL 由 D3 确认

      - name: 可搜物可达性（120 件够不着 0）
        run: "$GODOT" --headless --path Juhuo --quit -- --audit

      - name: 七空间串联
        run: "$GODOT" --headless --path Juhuo --quit -- --chain

      - name: 引导五步自检
        run: "$GODOT" --headless --path Juhuo --quit -- --tutrun
```

**要点：**

1. **`--quit` 必须写在 `--` 之前**。否则踩 Q-001：进程不退出，CI 挂死。
2. 需要在 CI 里装 Godot 4.7.2 **mono** 版（`project.godot` 是 C# 工程），且版本必须与
   `Juhuo/global.json` / `Juhuo.csproj` 的 `Godot.NET.Sdk/4.7.2` 一致。
   具体下载方式与 URL 由 D3 确认后落定，**不要写死在推测的 URL 上**。
3. 若下载 Godot 在 CI 上不可行，**备选方案**：加一个 `dotnet test` 层的集成测试，
   直接调用 `PointTable` 算可达性（"某点四周 N 格内是否有可站人的格"），
   把 `--audit` 的逻辑搬进 C# 单测。这条路不依赖 Godot 二进制，更稳，
   但需要 E1 提供 Core 层的可达性判定函数（现在可达性判定在 `Juhuo/Src/Game/` 里）。

**推荐**：优先做备选方案（Core 层可达性单测），因为它不引入 Godot 二进制依赖，
在 `ubuntu-latest` 上更可靠，也正好强化 S0-04 的 Core 骨架。

## 验收

- 故意把 `points.csv` 里某个点的坐标改到不可达格 → CI 变红。
- 故意把某个 NPC 的 `hub` 填错 → CI 变红。
- 三条命令在 CI 里都要能自动判定通过与否（不是靠人看日志）。
