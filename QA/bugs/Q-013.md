# Q-013 · 本机出包被 Godot 编辑器的 .NET SDK 识别卡住

- 严重度：P2（只影响出包，不影响开发、构建与测试）
- 发现者：P0（2026-10-28，E2 交付后复核时挖出）
- 状态：待解（出包线）

## 现象

```bash
godot --headless --path Juhuo --export-release "Windows Desktop" "Juhuo/build/juhuo.exe"
```

连续报四个错：

```text
ERROR: .NET Sdk not found. The required version is '9.0.5'.
ERROR: System.IO.FileNotFoundException: Could not load file or assembly
       'Microsoft.Build, Version=15.1.0.0' … 系统找不到指定的文件。
System.IO.FileNotFoundException: Cannot find the dotnet executable.
ERROR: Export .NET Project: Failed to build project. Check MSBuild panel for details.
ERROR: 准备模板: 给定的导出路径不存在。
```

## 核查过的事实

| 项 | 实测 |
|---|---|
| 导出模板 | **已装好**：`%APPDATA%\Godot\export_templates\4.7.2.stable.mono`，约 2GB，含 android/ios/linux 全平台 |
| 导出预设 | **已认得**：`Windows Desktop` 与 `Linux` 两个预设都在错误信息里被列出 |
| 本机 SDK | 只有 `8.0.427` 与 `9.0.300`（`dotnet --list-sdks`） |
| Godot 要的 9.0.5 | **上游不存在**：`dotnet-install.ps1 -Version 9.0.5` 四个下载源全部 404；9.0 通道最新是 `9.0.320` |
| 仓库自身构建 | 不受影响：`bash tools/dotnet.sh build` 0 警告 0 错误，97/97 单测通过 |
| 换 global.json 无效 | 8.0.427 / 9.0.300 / 9.0.5 三种写法下报错完全相同 → 是 Godot 编辑器侧的硬性要求，与 global.json 无关 |

## 判定

最后那句"导出路径不存在"是**连带报错**（构建失败 → 没有产物 → 模板阶段报路径不存在），真正的堵点是前三行：
Godot 4.7.2 的 .NET 出包链在编辑器进程里找不到它认得的 SDK 与 MSBuild 程序集。

## 本机 Docker 核查（2026-10-28 17:20 补）

用户指出本机有 Docker。核查结果：

| 项 | 结果 |
|---|---|
| Docker | 29.9.1，可执行文件在 `C://Program Files\Docker\Docker\resources\bin`（**不在 WorkBuddy 的 PATH 里**，所以第一次探测误判为"无 docker"） |
| 守护进程 | 正常，linux/x86_64，本地已有若干镜像 |
| 网络 | 配了 DaoCloud 加速器；`alpine:latest` 能拉（第一次超时，重试即成功）→ **docker 本身可用** |
| `barichello/godot-ci:mono-4.7.2` | **manifest 能解析出 5 层**（tag 真实存在），但 **blob 下载被加速器拒绝**：`这镜像不在白名单` |
| 容器内上网 | 不通（nuget / github 全超时） |

结论：**本机出包被"镜像加速器白名单"挡住，不是 Godot 的问题**。容器里自带 .NET SDK 与导出模板，
只要能拉到镜像，本机出包与 CI 出包走的是同一条路。

解法（任选其一）：
1. 给加速器提白名单（错误信息里给的入口：`github.com/DaoCloud/public-image-mirror/issues/2328`）；
2. 临时去掉 `~/.docker/daemon.json` 里的 `registry-mirrors` 并重启 Docker Desktop，改为走 Docker Desktop 自带代理直连；
3. 在能正常拉取 Docker Hub 的机器上 `docker save` 一份，拷过来 `docker load`。

## 绕过方案（按推荐顺序）

1. **在 CI 容器里出包**——`godot-ci` 镜像自带匹配的 SDK 与导出模板，与技术选型 §Step 9 的原设计一致。
   需要先确认该镜像的 .NET(mono) 变体可用（属 S0-06 的 headless 冒烟与出包 job）。
2. **让 Godot 编辑器自己管 SDK**——在编辑器里打开项目，让它按提示安装/选择它认得的 SDK 版本。
3. **本机手动装一个编辑器认得的 SDK**——版本号必须落在它接受的范围里（注意 9.0.5 上游不存在，
   很可能要 9.0.5xx 系列的 feature band）。

## 影响面

- 不影响：`dotnet build` / `dotnet test` / 编辑器内运行 / `--savetest` / `--audit` / `--chain`。
- 影响：出包（Windows / Linux 可执行文件），以及 CI 的 export job。
- 在此之前，**不得对外宣称"可以出包"**（这也是 Q1 在 G0 复核里提的同一条纪律）。
