# Q-012 · `tools/dotnet.sh` 把 Windows 专用的变量名导出到所有平台，在 Linux CI 上会指向不存在的路径

- 严重度：P2（脚本本身在本机 Windows 可用；但一旦被 CI 采纳就会踩，且 Q-010 正在往 CI 加 job）
- 发现者：Q1（2026-10-28 复核 `tools/dotnet.sh`，响应 P0 的兜底脚本通知）
- 状态：待修
- 依赖票：Q-010（headless 冒烟 job 若打算用脚本，会直接踩到本条）
- owner：D3（`tools/**` 属 D3，见 CANON §7）
- 证据报告：`QA/reports/2026-10-28-review.md` §5.4

## 现象

`tools/dotnet.sh` 用 `exec env` 无条件导出 7 个**Windows 专有**变量名：

```bash
exec env \
  "ProgramFiles(x86)=${PF86}" \
  "ProgramFiles=${PF}" \
  "ProgramW6432=${PF}" \
  "LOCALAPPDATA=${LAD}" \
  "APPDATA=${ARD}" \
  "DOTNET_CLI_HOME=${DCH}" \
  "NUGET_PACKAGES=${NPK}" \
  "$DOTNET_BIN" "$@"
```

其中 `LOCALAPPDATA` / `APPDATA` / `ProgramFiles` / `ProgramFiles(x86)` 在 **Linux 上完全无意义**；
`NUGET_PACKAGES` / `DOTNET_CLI_HOME` 则是**跨平台通用变量，在 Linux 上必须指向 Linux 路径**。

## 复现步骤

模拟 GitHub `ubuntu-latest` 的环境（那里 `USERPROFILE` **未设置**，`HOME=/home/runner`）：

```bash
$ env -i HOME=/home/runner PATH=/usr/bin:/bin \
    DOTNET_BIN=/d/tmp/fakedotnet.sh bash tools/dotnet.sh build x
NUGET_PACKAGES=[/c/Users/qwert\.nuget\packages]
DOTNET_CLI_HOME=[/c/Users/qwert]
LOCALAPPDATA=[/c/Users/qwert\AppData\Local]
```

**导出的 `NUGET_PACKAGES` 是 Windows 路径 `/c/Users/qwert\.nuget\packages`** ——
在 Linux 上 `/c` 不存在，且路径里混了反斜杠。

## 期望

1. `NUGET_PACKAGES` / `DOTNET_CLI_HOME` 在任何平台上都指向**该平台的有效路径**；
2. 纯 Windows 专有变量（`ProgramFiles*` / `LOCALAPPDATA` / `APPDATA`）**只在 Windows 上导出**。

## 实际

根因有两处：

1. **硬编码 Windows 用户路径**（`tools/dotnet.sh:42`）：

   ```bash
   else
     UP="/c/Users/qwert"
   fi
   ```

   `USERPROFILE` 未设置时（Linux 的常态），回退到这台机器的路径。
   这是**本机专属路径进了版本库** —— `grep -rn "qwert" tools/` 目前只有这一处，但它是「脚本作者是谁」的痕迹，
   换个机器/换个用户就失效。

2. **未做平台判断**：脚本无论在什么平台都导出同一组 Windows 变量名。

## 影响面

1. **在 Linux CI 上会把 NuGet 指向不存在的路径**。`ubuntu-latest` 上 `NUGET_PACKAGES` 指向
   `/c/Users/qwert\.nuget\packages`：runner 若以 root 跑会**真的创建**这个垃圾目录树并把包装进去
   （浪费磁盘、包缓存与 `~/.nuget/packages` 分裂）；若非 root 则可能直接权限失败。
2. **Q-010 正在往 CI 加 headless 冒烟 job**，若届时采纳 `bash tools/dotnet.sh ...` 作为统一入口，
   会直接踩到本条。**这是当前最现实的触发路径。**
3. `DOTNET_CLI_HOME=/c/Users/qwert` 同理，会让 .NET CLI 的配置/凭据落到错误位置。
4. 当前 CI **没有**用这个脚本（`grep dotnet.sh .github/workflows/ci.yml` → 无命中），
   所以**线上 CI 现在是干净的**。本条是**预埋风险**，不是已发生的故障。

## 修复建议

按平台分支，只在 Windows 上导出 Windows 变量；`NUGET_PACKAGES` / `DOTNET_CLI_HOME` 按平台取默认值：

```bash
# 平台判定
IS_WIN="false"
case "$(uname -s 2>/dev/null || echo Windows_NT)" in
  MINGW*|MSYS*|CYGWIN*|Windows_NT) IS_WIN="true" ;;
esac

if [ "$IS_WIN" = "true" ]; then
  if [ -n "${USERPROFILE:-}" ]; then UP="$USERPROFILE"; else UP=""; fi
  PF="${ProgramFiles:-C:\\Program Files}"
  PF86="${ProgramFilesX86:-C:\\Program Files (x86)}"
  LAD="${LOCALAPPDATA:-${UP}\\AppData\\Local}"
  ARD="${APPDATA:-${UP}\\AppData\\Roaming}"
  NPK="${NUGET_PACKAGES:-${UP}\\.nuget\\packages}"
  DCH="${DOTNET_CLI_HOME:-${UP}}"
  exec env "ProgramFiles(x86)=${PF86}" "ProgramFiles=${PF}" "ProgramW6432=${PF}" \
         "LOCALAPPDATA=${LAD}" "APPDATA=${ARD}" \
         "DOTNET_CLI_HOME=${DCH}" "NUGET_PACKAGES=${NPK}" \
         "$DOTNET_BIN" "$@"
else
  # Linux / macOS：只补真正需要的通用变量，路径用 $HOME
  exec env "DOTNET_CLI_HOME=${DOTNET_CLI_HOME:-${HOME:-/tmp}}" \
         "NUGET_PACKAGES=${NUGET_PACKAGES:-${HOME:-/tmp}/.nuget/packages}" \
         "$DOTNET_BIN" "$@"
fi
```

要点：
- **删掉硬编码的 `/c/Users/qwert`**，`USERPROFILE` 缺失时在 Windows 上应当**报错退出**并说明原因，
  而不是猜一个别人的路径。
- Linux 分支**不要**导出 `ProgramFiles*` / `LOCALAPPDATA` / `APPDATA`（在 Linux 上是纯噪音，
  且可能误导后续工具）。

## 验收

```bash
# Linux 侧
$ env -i HOME=/home/runner PATH=/usr/bin:/bin bash tools/dotnet.sh --version
# 必须报出 /home/runner 下的路径，且不得出现 "C:\" 或 "qwert"

# Windows 侧（本机）
$ bash tools/dotnet.sh build Juhuo/Juhuo.sln --nologo
# 仍然 0 警告 0 错误
```

## 附：同一脚本的另一处小问题（非独立成票）

`--print-env` 打印的是**继承值**，不是**实际生效值**：

```bash
$ bash tools/dotnet.sh --print-env
LOCALAPPDATA=<空>          # ← 打印的是继承来的（空）
DOTNET_CLI_HOME=<空>
NUGET_PACKAGES=<空>

# 但子进程实际收到的是（用假 dotnet 探针测得）：
EFFECTIVE LOCALAPPDATA=[C:\Users\qwert\AppData\Local]
EFFECTIVE DOTNET_CLI_HOME=[C:\Users\qwert]
EFFECTIVE NUGET_PACKAGES=[C:\Users\qwert\.nuget\packages]
```

脚本头注释写的是「查看补了哪些变量」，但实现只 `echo` 了**原始环境变量**，
没打印 `${LAD}` / `${ARD}` / `${DCH}` / `${NPK}` 这些**计算后的生效值**。
排查问题时看这个输出会得出错误结论。修本条时一并改掉即可（打印 `$LAD` 等计算值）。
