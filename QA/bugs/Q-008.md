# Q-008 · CI 从仓库根执行 `dotnet build`，不受 `Juhuo/global.json` 的 SDK 锁定约束

- 严重度：P2（CANON 明文要求锁 8.0.x，当前锁在 CI 里是失效的）
- 发现者：Q1（2026-10-28 CI 预演）
- 状态：待修
- 依赖票：无
- owner：E1 / P0（`global.json` 属冻结件，见 CANON §7）
- 证据报告：`QA/reports/2026-10-28-review.md` §5.1

## 现象

`Juhuo/global.json` 锁的是 SDK 8.0.427：

```json
{
  "sdk": {
    "version": "8.0.427",
    "rollForward": "latestFeature"
  }
}
```

CANON §4 硬数字写明：「引擎 Godot 4.7.2 (.NET) / C# 12 / **net8.0 / `global.json` 锁 8.0.x**」。

但 CI 的命令全部从**仓库根**执行：

```yaml
- name: 编译
  run: dotnet build Juhuo/Juhuo.sln --nologo
- name: 单测
  run: dotnet test Juhuo/Tests/Core.Tests/Core.Tests.csproj --nologo -v q
```

而 **dotnet 的 SDK 解析是从「当前工作目录」向上找 `global.json`，不是从工程路径找**。
`Juhuo/global.json` 在 `Juhuo/` 下 → 从仓库根执行时**根本看不到它**。

## 复现步骤

```bash
$ cd D:/我的小想法游戏 && dotnet --version
9.0.300          ← 锁失效

$ cd D:/我的小想法游戏/Juhuo && dotnet --version
8.0.427          ← 锁生效

$ git ls-files | grep global.json
Juhuo/global.json    ← 仓库根没有 global.json
```

## 期望

CI 的 `dotnet build` / `dotnet test` 跑在 CANON 规定的 SDK 8.0.x 上，无论从哪个目录发起。

## 实际

CI 实际用哪个 SDK，取决于 runner 上恰好有什么、以及 `setup-dotnet` 装了什么，
**与仓库里的 `global.json` 无关**。

当前 `ci.yml` 写的是 `dotnet-version: '8.0.x'`，恰好与 CANON 一致 ——
**但这是巧合，不是约束**。

## 影响面

- runner 镜像升级、`setup-dotnet` 默认值变化、或有人把 `dotnet-version` 改成 `9.0.x`，
  CI 都会**静默用错 SDK**，而 CANON 明文要求锁 8.0.x。
- **「CI 绿」目前不能等价于「在规定 SDK 上通过」**。这直接影响 G0 验收依据的可信度
  （见 `QA/reports/2026-10-28-review.md` §8）。
- 未来若引入依赖具体 SDK 行为的特性（如某些 C# 12 / .NET 8 API），跨 SDK 版本会产生
  "本地过 CI 挂" 或反之的漂移。

## 修复建议

二选一：

**A. 把 `global.json` 上提到仓库根**（推荐）

```bash
cp Juhuo/global.json global.json
git rm Juhuo/global.json      # 或保留，但根目录那份才是被读到的
```

根目录那份对**所有**工作目录生效，CI 与本地行为一致。
注意：SDK 解析只看当前目录向上，所以放在根目录后，`cd Juhuo` 也会向上找到根目录那份，行为统一。

**B. CI 每个 step 加 `working-directory: Juhuo`**

```yaml
- name: 编译
  working-directory: Juhuo
  run: dotnet build Juhuo.sln --nologo
```

但这样命令路径与本地/文档里"仓库根加 `Juhuo/` 前缀"的约定不一致，
且 `Juhuo/.gitattributes` 之外的路径写法要重新统一。**不如 A。**

## 验收

```bash
$ cd <仓库根> && dotnet --version
8.0.427      # 必须与 CANON 一致
```

## 备注

- 现有 `Juhuo/global.json` 的内容本身是对的（8.0.427 + `rollForward: latestFeature`），**只是位置不对**。
- 本条与 `举火_技术选型与前期准备_v1.0.md` 的 `dotnet.sh` 兜底方案无冲突：
  `tools/dotnet.sh` 解决的是"受限环境 NuGet 初始化失败"，本条解决的是"SDK 版本选哪个"，两回事。
